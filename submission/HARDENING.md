# Security Hardening Register (HARDENING.md)

This register tracks all security vulnerabilities, architectural defects, and hardening measures implemented in the Hostel Grievance Management Application backend (`src/server`).

| ID | Finding | Risk | Change | Verification | Residual Risk |
|----|---------|------|--------|--------------|---------------|
| **ID-001** | Broken Object Level Authorization (IDOR) on Grievance Viewing & Comments | **High**: Any authenticated student could view and comment on grievances belonging to other students by guessing or enumerating grievance IDs. | Enforced RBAC check (`assertCanViewGrievance`) in `GrievanceService.getGrievanceById`, `listComments`, and `addComment`. Integrated `AuthMiddleware.checkGrievanceAccess()`. | `app.test.ts`: `student cannot access another student’s grievance` (Returns HTTP 403). | Minimal. Access controlled by verified session user ID. |
| **ID-002** | Privilege Escalation in Grievance Patch Endpoint | **High**: Students could alter grievance status (`open` -> `resolved`) and edit grievance text owned by other students. | Restricted status updates strictly to `warden` role in `GrievanceService.updateGrievance`. Added ownership check for `student` role. | `app.test.ts`: `status changes work for wardens and are forbidden for students` (Returns HTTP 403). | Minimal. Role check enforced at middleware and service layer. |
| **ID-003** | Unauthorized Attachment Content Download | **High**: Any logged-in user could download stored file attachments for any grievance via `/api/attachments/:id`. | Updated `AttachmentService.getAttachment` to resolve parent grievance ID and enforce student ownership/warden check prior to file reading. | `app.test.ts`: `attachment metadata and storage work` stolen check (Returns HTTP 403). | Low. File path traversal guarded with `resolve` check. |
| **ID-004** | Incomplete Session Invalidation on Logout | **Medium**: Logout cleared HTTP cookie but left the session token valid in SQLite database. | Updated `AuthService.logout` to execute `destroySession(db, token)` to delete session row from database. | `app.test.ts`: `current-user works after login and fails after logout`. | Low. Short session TTL (24h) enforced as baseline. |
| **ID-005** | Missing API Rate Limiting | **Medium**: Sensitive endpoints (login, API routes) had no request rate controls, exposing application to brute force and denial of service attacks. | Implemented `RateLimitMiddleware` sliding window limiter. Applied strict limit (15 requests/15min) on `/api/login` and general limit (200 requests/15min) on `/api/*`. | `app.test.ts`: `enforces rate limiting on excessive login attempts` (Returns HTTP 429). | Low. In-memory store resets on server restart. |
| **ID-006** | Missing Security Response Headers | **Low**: Server responses lacked standard defensive HTTP headers. | Added global security header middleware in `app.ts` (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `X-XSS-Protection: 1; mode=block`, `Referrer-Policy`). | `app.test.ts`: `security headers are present in responses`. | None. |
| **ID-007** | Windows SQLite Resource Lock in Test Cleanup | **Low**: `afterEach` hook failed during test directory cleanup on Windows due to unclosed SQLite file handle. | Added explicit `db.close()` in test lifecycle hooks prior to `rmSync`. | `npx vitest run` passes 100% on Windows without `EPERM` errors. | None. |
